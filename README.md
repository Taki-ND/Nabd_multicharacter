# Nabd-Multicharacter

نظام تسجيل دخول تلقائي لسيرفرات **QBCore**، بدون شاشة اختيار شخصيات معقدة:

- أول مرة يدخل فيها اللاعب → يتم إنشاء شخصية له **تلقائياً** باسمه في الديسكورد (أو اسمه باللعبة إذا ما فيه توكن بوت).
- إذا رجع مرة ثانية → يشوف نفس الشخصية ويكمل عليها مباشرة.
- بكل الحالتين، اللي يشوفه اللاعب هو كرت بسيط باسمه وزر **"ابدأ اللعب"**.


---

## 1. المتطلبات (Dependencies)

- `qb-core`
- `oxmysql`

لازم يكون عندك جدول `players` الأساسي من qb-core (ما يحتاج جدول جديد، السكربت يشتغل على نفس الجدول).

---

## 2. التركيب (Installation)

1. حط مجلد `Nabd-multicharacter` داخل مجلد `resources`.
2. **أوقف/احذف** أي مورد اختيار شخصيات ثاني تستخدمه حالياً (مثل `qb-multicharacter` الافتراضي)، عشان ما يصير تعارض بين واجهتين تسجيل دخول.
3. بملف `server.cfg` ضيف:

```cfg
ensure qb-core
ensure oxmysql
ensure Nabd-multicharacter
```

تأكد إنه يشتغل بعد `qb-core` و `oxmysql`.

---

## 3. إعداد اسم الديسكورد (اختياري لكن موصى فيه)

عشان يجيب اسم الديسكورد الحقيقي (الاسم المعروض / Global Name) لازم بوت ديسكورد:

1. روح [Discord Developer Portal](https://discord.com/developers/applications) → أنشئ Application جديد.
2. من تبويب **Bot** → أنشئ بوت وخذ الـ **Token** (احتفظ فيه بمكان آمن، لا تشاركه أبداً).
3. افتح `config.lua` وحط التوكن:

```lua
Config.DiscordName.Enabled = true
Config.DiscordName.BotToken = 'ضع_التوكن_هنا'
```

> ملاحظة: البوت **ما يحتاج** يكون موجود بنفس السيرفر مع اللاعبين، بس يحتاج يكون فعّال (شغّال) عشان يقدر يستخدم الـ API.

إذا ما تبي هالخاصية أصلاً، خلها:
```lua
Config.DiscordName.Enabled = false
```
وبهالحالة بيستخدم اسم اللاعب داخل اللعبة (Rockstar/Steam) تلقائياً.

---

## 4. إعدادات مهمة بملف config.lua

| الإعداد | الوصف |
|---|---|
| `Config.DefaultCharInfo.lastname` | اللقب الافتراضي لأي شخصية جديدة |
| `Config.DefaultCharInfo.birthdate` / `gender` / `nationality` | باقي بيانات الشخصية الافتراضية |
| `Config.HiddenCoords` | مكان يتجمد فيه اللاعب أثناء عرض الواجهة (بالسماء افتراضياً) |
| `Config.DefaultSpawn` | مكان ظهور اللاعب بعد "ابدأ اللعب" |
| `Config.EnableStarterItems` / `Config.StarterItems` | عناصر تنعطى تلقائياً للشخصيات الجديدة فقط |
| `Config.Webhook` | رابط ويبهوك ديسكورد لتسجيل كل شخصية جديدة تتنشئ |
| `Config.Stats.Enabled` | فعّلها إذا عندك جدول قتلات/وفيات جاهز (مثلاً من `qb-pvp`) عشان تظهر بالواجهة |
| `Config.Stats.Table` / `CitizenIdColumn` / `KillsColumn` / `DeathsColumn` | اسم الجدول والأعمدة اللي فيها القتلات والوفيات |

## 5. واجهة الشخصية (كاميرا + Callouts)

الواجهة الحين شفافة بالكامل وتعرض شخصيتك الحقيقية بالعالم (زي شاشات اختيار الشخصية المعروفة)، مو كرت مغلق:

- الكلايند ينشئ **كاميرا سكربتية** (`CreateCharCam`) تقف مقابل الشخصية بمكان `Config.HiddenCoords` وتتجه نحوها تلقائياً.
- فوق الشخصية تطلع خطوط توصيل تقنية (Leader Lines) بستايل Tactical HUD تشاور على: **الاسم**، **القتلات**، **الوفيات**.
- إحداثيات الخطوط والليبلات محسوبة كنسب مئوية من الشاشة (بملف `css/style.css` تحت `.callout--name/deaths/kills` وبملف `index.html` بالـ `<svg class="callout-svg">`)، مضبوطة على إطار كاميرا افتراضي متوسط اللقطة (نصف جسم للأعلى تقريباً).
- إذا غيّرت زاوية أو مسافة الكاميرا بدالة `CreateCharCam` بملف `client/main.lua`، بتحتاج تعدّل هالنسب شوي عشان الخطوط تطلع بنفس مكان الكتف/الصدر بالظبط.

> إذا `Config.Stats.Enabled = false`، القتلات والوفيات تطلع دايماً `0` (مناسب لشخصية جديدة).

---

## 6. آلية العمل (كيف يشتغل تقنياً)

1. عند دخول اللاعب، الكلايند يجمّده ويوقفه أمام كاميرا الشخصية بمكان `Config.HiddenCoords`.
2. السيرفر يتحقق من جدول `players` عبر الـ `license` identifier:
   - **موجود** → يرجع بيانات شخصيته الحالية (لا يتغير شي).
   - **غير موجود** → يجيب اسم الديسكورد (أو اسم اللعبة كـ fallback)، ويبني `charinfo` جديد، ويخزنه **مؤقتاً بالسيرفر فقط** لحين ما يضغط "ابدأ".
3. لما يضغط اللاعب "ابدأ اللعب"، الكلايند يرسل حدث فاضي بدون أي بيانات، والسيرفر يستخدم البيانات اللي بناها هو بنفسه لعمل:
   - `QBCore.Player.Login(src, false, newData)` لشخصية جديدة، أو
   - `QBCore.Player.Login(src, citizenid)` لشخصية موجودة.
4. `QBCore.Player.Login` يتكفل تلقائياً بتوليد `citizenid`، تعبئة الأموال الافتراضية، وحفظ الصف بجدول `players`.
5. بعدها يوصل حدث للكلايند يدمّر الكاميرا ويسبون اللاعب بمكان `Config.DefaultSpawn` ويفك التجميد.

## 7. ملاحظات أمنية (Security Notes)

- **ما فيه أي بيانات حساسة توصل من الكلايند للسيرفر.** حدث "ابدأ" ما يرسل أي Payload، فما يقدر لاعب يزوّر `citizenid` أو بيانات شخصية.
- التحقق من الشخصية الموجودة يتم عبر `license` identifier فقط (السيرفر هو اللي يجيبه، مو الكلايند).
- `QBCore.Player.Login` نفسه يتحقق داخلياً إن الـ `license` يطابق صاحب الـ `citizenid` قبل ما يسمح بتسجيل الدخول (حماية من استغلال انتحال شخصية غيرك).
- توكن بوت الديسكورد يبقى بالسيرفر فقط (`server/main.lua`) ولا ينكشف للكلايند إطلاقاً.
- أي طلب HTTP للديسكورد أو الويبهوك يصير من السيرفر فقط.

---

## 8. ملاحظات الأداء (Performance Notes)

- لا يوجد أي حلقة `while true` بدون `Wait` — حلقة تعطيل التحكمات تستخدم `Wait(0)` فقط أثناء ظهور الواجهة، وترجع لـ `Wait(500)` بعد إغلاقها.
- استعلام قاعدة البيانات (`SELECT ... LIMIT 1`) يصير مرة وحدة فقط لكل لاعب عند أول اتصال، مو بشكل متكرر.
- طلب الديسكورد HTTP يصير مرة وحدة فقط (عند أول دخول لشخصية جديدة)، ولا يتكرر لاحقاً.
- كل الاستعلامات عبر `oxmysql` غير متزامنة (async)، ما توقف الترد الرئيسي بالسيرفر.

---

## 9. استكشاف الأخطاء (Troubleshooting)

- **الواجهة ما تطلع أبداً:** تأكد إن `ensure Nabd-multicharacter` بعد `qb-core` و `oxmysql` بملف `server.cfg`، وتأكد ما فيه مورد ثاني (مثل `qb-multicharacter`) شغّال بنفس الوقت.
- **اسم الديسكورد ما يطلع صحيح:** تأكد التوكن صحيح وإن اللاعب فاتح الديسكورد وقت الدخول (identifier `discord:` يحتاج ديسكورد شغّال بجهازه).
- **اللاعب ما يسبون بعد الضغط على ابدأ:** افتح الكونسول (F8) وشوف إذا فيه إيرور بـ `QBCore.Player.Login`، غالباً يكون بسبب مورد ثاني يتعارض بجدول `players`.
